# Polymarket gateway

The adapter uses the installed unified TypeScript SDK `@polymarket/client@0.12.0`. Discovery is Gamma, books/market fee parameters/orders are CLOB, and history/positions use the SDK's Data API v2 cursor pagination. No credentials or chain transactions were used during implementation.

## Integration

Import `PolymarketGateway`, `createLiveGateway`, `arbitrageQuote` and `GatewayError` from `packages/trading/src/index.ts`. The public constructor needs no wallet. `createLiveGateway` requires explicit wallet address, private key, Polygon RPC URL, and existing CLOB credentials. Secret configuration belongs in the server environment only. Contract wallet code is checked before SDK authentication; an undeployed contract wallet is blocked rather than implicitly deployed. EOA accounts explicitly pass their own signer address. The factory never grants allowances or deploys wallets.

Map existing `POLYMARKET_PRIVATE_KEY`, `POLYMARKET_WALLET_ADDRESS`, and `POLYGON_RPC_URL` to the factory. Add server-only `POLYMARKET_CLOB_API_KEY`, `POLYMARKET_CLOB_API_SECRET`, and `POLYMARKET_CLOB_API_PASSPHRASE` for its `credentials: {key, secret, passphrase}`. `POLYMARKET_RELAYER_API_KEY` alone is not a CLOB credential and does not arm heartbeat protection. Provide factory relayer: {key,address} using POLYMARKET_RELAYER_API_KEY and POLYMARKET_RELAYER_API_KEY_ADDRESS; the exported SDK relayerApiKey adapter supplies RELAYER_API_KEY / RELAYER_API_KEY_ADDRESS authorization. Readiness exposes gaslessConfigured separately from approvals and balances. The SDK does not retry automatically. The worker shares an `ExchangeRequestControl` between public and wallet gateways and persists cooldowns in PostgreSQL. Rate-limit rejection honors the supplied delay, including across restart; absent delays use bounded exponential backoff. Matching-engine restart and explicit post-only restrictions block incompatible new orders. The app never silently changes FOK orders into maker orders, infers cancellation permission from an unclassified 503, or replays a signed mutation. A later opportunity requires fresh risk authorization. Dashboard readiness exposes active cooldowns.

`walletReadiness(address)` reads geographic eligibility and chain approval state. It does not approve tokens. An actual cash/token balance check, ownership/authorization, policy version, exposure, drawdown, and strategy risk gate must also pass in the worker before signing.

Discovery selects standard Yes/No markets ending between 24 hours and 30 days ahead, excludes negative risk and sports, and caps inspected candidates at 500. Missing/unsupported metadata is blocked. `getMarket` can retrieve an existing supported market for reconciliation outside the discovery horizon. Tick size and minimum shares come from a freshly fetched CLOB book; fees come from `fetchMarketInfo`. Unknown nonzero fee curves are blocked. The current fee formula is `shares * rate * price * (1-price)`. The reserve estimate rounds upward to five decimals; this is conservative and is not an actual charged fee. For 100 shares at 0.50 and rate 0.07 the estimate is 1.75000 USD.

## Orders and ambiguous requests

`prepareOrder(intent)` validates live mode, geoblock, closed-only account mode, market state, token/condition/rules identity, tick, minimum size, share precision, maximum cost and post-only compatibility. It signs a limit-sized order without posting. GTC/GTD/FOK/FAK are explicit posting policies; `createLimitOrder` receives shares, never BUY collateral amount. FOK/FAK policy is set on the signed order's posting envelope. GTD must expire at least 180 seconds ahead; exchange security threshold makes effective expiry 60 seconds earlier.

Persist the complete `PreparedOrder` and attempt state atomically **before** `submitPrepared`. `PreparedOrder.hash` is a SHA256 payload integrity fingerprint, **not** a CLOB order ID or EIP712 order hash. The factory captures the public `Signer.signTypedData` payload and computes `exchangeOrderHash` with viem `hashTypedData`, retaining the SDK-owned actual domain, Order structure and message. For POLY1271, the SDK wraps Order contents in TypedDataSign; the native Order digest hashes those contents with the exchange domain. Persist `exchangeOrderHash` and `exchangeAddress` before POST so ambiguous recovery can look up the native hash. Verify an accepted response's authoritative `orderId` against this hash. Do not look up a CLOB order using the payload fingerprint. A gateway constructed with an external client without the capture callbacks cannot supply this native hash and must conservatively block automatic ambiguous recovery.

The adapter attempts each fingerprint once per process. Durable idempotency is the worker/database's responsibility across restarts. A POST timeout, transport loss, or unclassified exchange exception is ambiguous: stop new risk, reconcile and require authoritative exchange evidence; never blindly retry. A rejected response has `ok:false`; accepted does not mean settlement confirmed. Inspect the SDK response's status, trade IDs and transaction hashes. Use `getOrder(orderId)` for an order absent from the open-order snapshot. Cancellation can be partial; inspect `canceled` and `notCanceled`, then reconcile.

`reconcile()` returns full paginated `orders`, `trades`, `positions`, `balances`, and `observedAt`. It blocks rather than silently truncating beyond 10,000 rows. SDK `OpenOrder` fields include `id`, `assetId`, `conditionId`, `originalSize`, `sizeMatched`, `associateTrades`, `status`, `side` and `price`. SDK `ClobTrade` includes `id`, `assetId`, `takerOrderId`, `traderSide`, `size`, `price`, `status`, `transactionHash`, `makerOrders`, and `feeRateBps`; a maker fill is the matching own `makerOrders[].orderId` with its `matchedAmount`, not the total taker size. Preserve matched/mined/retrying/confirmed/failed as separate states. `feeRateBps` is a rate, not charged USD. Actual fee is unavailable in the CLOB trade response and must remain unknown until authoritative accounting/activity evidence exists.

`normalizedReconcile()` adds wallet-specific `fills` with the authoritative order ID, shares, price, side, status, transaction hash and `confirmed` flag. `actualFeeUsd` remains null unless authoritative receipt evidence matches. Pass persisted {orderId,exchangeAddress} contexts to normalizedReconcile: confirmed receipt OrderFilled logs must match the signed exchange, native order hash, wallet maker, token, side and exact share total. The worker groups all CLOB rows by native order and transaction, requires their total shares to match verified receipt logs after 12 confirmations, then posts each log once using transaction hash plus log index. Exact receipt collateral notional is posted directly, avoiding weighted-average rounding. Pending CLOB rows retain NULL fee and are removed only after all their matching receipt logs are journaled; no fee allocation is invented. getOrderSettlement(transactionHash,orderId,exchangeAddress) returns exact per-log fees and shares for aggregate accounting, keyed by transactionHash/logIndex. `getResolution(id)` reads Gamma terminal state without requiring a closed market's order book. Redemption requires closed state, UMA status resolved and valid complementary payouts summing to one; proposed/disputed prices cannot trigger redemption. Invalid-market 0.5/0.5 payouts are supported. `getTransactionReceipt(hash)` reads Polygon status, confirmations and gas cost in wei; record gas cost separately from trading fees and apply a confirmation/reorg policy before releasing final reserves. SDK transaction handles provide `transactionHash`, `transactionId` and `wait()`; the settled outcome contains those two IDs. A missing transaction hash or lost submission result remains unresolved.

## Feeds and order deadman

`startMarketFeed(assetIds)` and `startUserFeed(conditionIds)` return SDK native async iterable subscription handles. Consume with `for await`, close on shutdown, catch stream failures, and mark feed freshness invalid. SDK subscriptions handle websocket transport heartbeat/reconnection; a websocket ping is not a CLOB order deadman. Always refetch HTTP books before trading, including after reconnect, tick changes or market resolution. `OrderBook.observedAt` preserves the exchange timestamp when present, so a fresh HTTP request does not pretend an older book is recent. The worker separately records retrieval time and invalidates absent/stale feed information.

`orderHeartbeat()` uses the documented authenticated fallback `POST https://clob.polymarket.com/v1/heartbeats`. The body is exactly serialized `{heartbeat_id: latestId}`; L2 signing concatenates timestamp, POST, `/v1/heartbeats`, and that body, then URL-safe padded HMAC-SHA256 using the base64 decoded API secret. The signer address and credentials must be the same account that owns the orders. Store the returned rotating ID in process memory. Call every five seconds. A valid heartbeat absent for ten seconds triggers cancellation of those credentials' open orders, checked every five seconds. A 400 response's expected ID is saved, but the failed call still blocks; the next explicitly scheduled heartbeat can use that ID. GTC/GTD prepare/submit require an accepted heartbeat within seven seconds. Stop new resting orders on failure and reconcile cancellation. The worker must run the recurring heartbeat loop; merely configuring credentials does not arm it.

`merge(conditionId, shares)` and `redeem(conditionId)` submit chain/relayer operations through the SDK only when explicitly invoked. Persist operation identity/state before invocation and reconcile transaction handles; a returned handle is not confirmed settlement. The worker persists expected pre/post cash and token balances plus a position fingerprint before submission. A successful receipt with 12 confirmations must also match the observed cash and token deltas and unchanged local position identity before the settlement journal is posted. Missing baselines or lost submit handles remain unresolved; no blind retry is allowed. Only explicitly configured relayer-backed contract wallets qualify for gasless settlement accounting; an EOA sends its own chain transaction and its gas cost must not be declared zero. Merge amount uses exact six-decimal units.

## Manual verification

1. Without credentials, discover a market and compare its condition, outcomes, tick and minimum shares against the public CLOB/Gamma response. Fetch both books and a history page.
2. Confirm unsupported markets and missing fee/eligibility data block new trade decisions.
3. With a separately provisioned account, inspect readiness and balances read-only before enabling live mode. Verify undeployed contract wallets are blocked and no deployment/approval is attempted.
4. In an isolated approved low-value live acceptance run, arm heartbeats, persist the signed order before posting, compare authoritative order/trade IDs, test partial cancellation, then stop heartbeat and verify exchange cancellation within the documented timeout/check window.
5. Simulate lost POST acknowledgement at the integration boundary; ensure durable state becomes ambiguous and no second submission occurs. Reconcile settlement and maker-specific fill sizes before releasing reserves.

Steps involving credentials, real orders, wallet deployment, approvals and chain transactions remain unverified until the user authorizes and executes that live acceptance run.

## Recovery and dispatch deadlines

The consumed 15-second risk permit is checked again after signing and immediately before the final POST, including after geographic preflight. Prepared payloads must carry the persisted permit expiry. A stale book or expired permit rejects the order without exchange submission. Paper preparation likewise cannot use an expired permit for a new fill; previously persisted paper fills are recovered idempotently.

While holding the single-wallet worker lease, startup releases reservations for live orders left in preparing, preserves submitting orders as ambiguous, and changes prepared settlements to retryable failures only when the new preparation metadata proves that external dispatch did not occur. Legacy prepared records without that proof stay blocked. Confirmed dispatch identities are polled in later portfolio pulses; waiting for chain finality no longer occupies the operations queue. Forecast resolution reads run in the separate discovery queue, five markets in parallel per bounded cursor batch.

Official restart/restriction contract checked on 2026-10-04: [Polymarket matching-engine guidance](https://docs.polymarket.com/trading/matching-engine). Local fixtures establish control-flow behavior, not actual venue acceptance; see [verification.md](verification.md).
