# Public repository and first VPS release

Verified on 2026-10-04 (Asia/Jakarta). Repository: [revanapriyandi/polymarket-agent](https://github.com/revanapriyandi/polymarket-agent), visibility **PUBLIC**, branch `main`. Dashboard: [pm.rnevio.com](https://pm.rnevio.com). Access requires the owner account; public signup is disabled. Login credentials are delivered in an ignored local file, never in this repository.

## Changes

- Every Settings tab has **Cara mengisi**. The nested drawer includes initial steps, searchable field explanations, units, examples, valid ranges, troubleshooting and documentation links. Closing help retains the current unsaved form and returns keyboard focus to its help button.
- Guides cover risk/capital, paper/live distinctions, strategy allocation, worker settings, official/custom AI protocols, API secrets/headers, provider prices/budgets, capabilities, assignment/fallback, Tavily, public RSS/Atom and wallet readiness. Examples are explanatory and do not modify Settings.
- Git and Docker exclude real environment files, `.runtime`, local package caches, screenshots, backups and key files. An initial publication scan checked all staged files against local secrets and common private-key/token patterns; no secret matches were found.
- Added resource-limited Compose configuration for an existing host Nginx, a loopback-only API port, a PostgreSQL 18 backup image, daily backup helper/units and deployment/recovery instructions.

## Remaining configuration and evidence boundaries

AI provider keys/model assignment/budgets, Tavily credentials and live wallet credentials remain unconfigured. Public feeds and market data work, but paid research/forecasting cannot be claimed ready until configured and probed. `ENABLE_LIVE_EXECUTION=false`, live risk profile is empty, and strategy promotion gates remain blocked. No 30-day paper record, 100 completed trades, live transaction, real settlement or real profit is established by this deployment.

The backup timer writes encrypted archives on the VPS. A local encrypted archive can be copied separately for recovery, but continuous external backup replication has not been configured. Keep the backup key and provider encryption key in a separate recovery location. The restore drill confirms database integrity, not a full host disaster-recovery exercise.

## Manual owner check

1. Open the HTTPS dashboard and sign in with the separately delivered account.
2. Open Settings, select any tab, and click **Cara mengisi**. Search a field name, then return to confirm your draft is retained.
3. Review PAPER capital/limits. Confirm fresh agent timestamps and SSE status; configure and probe provider/search connections before assigning AI roles.
4. Use the [VPS runbook](vps.md) for upgrades, daily-backup inspection and isolated restore. Treat live activation as a separate gated action.
